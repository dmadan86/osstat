# Instructions for coding agents

Read this before making changes. It encodes the constraints that are not obvious
from the code, and the ones that matter most are about not destroying user data.

## Work milestone by milestone

[ROADMAP.md](ROADMAP.md) defines milestones M0–M5. **Do not start milestone N+1
until milestone N's gate passes.** A gate is: code, tests, updated docs, and
green CI on Windows, Linux and macOS. Gates are stated per milestone in the
roadmap and are not negotiable — they exist because each milestone's correctness
is what the next one builds on.

## Non-negotiable engineering rules

1. **Every new Rust module ships with tests in the same change.** Not a follow-up.
2. **No `unwrap()`, `expect()`, `panic!()`, `todo!()` or `unimplemented!()`
   outside tests.** These are clippy errors in CI. Return an error instead. Test
   modules opt out with a local `#![allow(...)]`.
3. **`clippy::pedantic` warnings are triaged, not suppressed globally.** If a
   lint is genuinely wrong for a case, add a local `#[allow]` with a comment
   explaining why.
4. **Every filesystem-mutating code path needs a dry-run branch and fixture-tree
   tests before it is wired to the UI.** Assert the exact set of surviving files,
   not a count.
5. **Never widen the elevation helper's command protocol** without updating
   [SECURITY.md](SECURITY.md) and
   [ADR-006](docs/adr/ADR-006-privilege-elevation.md). Its narrowness is the
   security property.
6. **Update the rule-authoring documentation whenever the manifest schema
   changes.** External contributors write against the documented format.

## Where code belongs

| Put it in                | When                                                   |
| ------------------------ | ------------------------------------------------------ |
| `crates/osstat-core`     | Portable logic and domain types. No `cfg(target_os)`.  |
| `crates/osstat-platform` | Anything OS-specific, behind a trait declared in core. |
| `src-tauri`              | Only IPC adapters. No system logic.                    |
| `ui`                     | Presentation only. No system logic.                    |

If `osstat-core` needs a `cfg(target_os)`, the logic belongs in
`osstat-platform` behind a trait ([ADR-003](docs/adr/ADR-003-platform-abstraction.md)).
If `src-tauri` is growing logic worth testing, it belongs in `osstat-core`.

## After changing an IPC type

TypeScript types are generated from the Rust structs. Run `just bindings` and
commit the regenerated `ui/src/bindings/`. CI fails on a stale diff.

## Before claiming something works

Run `just ci` — the same checks CI runs. Do not report a milestone gate as passed
based on a partial run; note explicitly which platforms were actually verified,
since only CI can verify all three.

## Commits

Conventional Commits, enforced by a hook and by CI. Sign off with `git commit -s`
(DCO). The pull request title becomes the squashed commit on `main`, so it must
itself be a valid Conventional Commit.

Do not add co-author or "generated by" trailers to commits.

## Read the ADRs

[`docs/adr/`](docs/adr/) records why the project is built the way it is. Before
changing deletion safety, privilege elevation, or the platform abstraction, read
the corresponding record — and write a new one as part of the change rather than
after it.
