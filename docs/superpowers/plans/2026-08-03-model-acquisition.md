# Model acquisition — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Download pinned GGUF models from the LLM advisor into a folder chosen
in Settings, and run one straight after download.

**Architecture:** `osstat-inference` gains `models` (manifest types + URL
derivation), `model_store` (records on disk) and resumable verified download,
reusing `download_verified`'s discipline and `fs4`'s space check.
`src-tauri/src/models.rs` exposes commands and `model:*` events beside
`runtime.rs`. The advisor gains download/run controls; Settings gains a folder
picker.

**Tech Stack:** Rust 2024, `reqwest` 0.13 + `rustls`, `sha2`, `fs4`, `serde`;
React 19 + TypeScript, Vitest; Tauri 2; `ts-rs` 12.

**Spec:** `docs/superpowers/specs/2026-08-03-model-acquisition-design.md` — read
it before starting. Every "why" lives there; this file is the "how".

## Global Constraints

- **No `unwrap()`/`expect()`/`panic!()` outside `#[cfg(test)]`.** Test modules
  opt out with exactly `#![allow(clippy::unwrap_used, clippy::expect_used)]`.
  **Never add `clippy::panic`** — the workspace sets it to `warn` and CI runs
  `-D warnings`, so `panic!` and `assert!(false, …)` fail the build even in
  tests. Use paired `assert!`s instead.
- **`osstat-inference` carries `#![forbid(unsafe_code)]`.** Never weaken it.
- **`git commit -s`** (DCO). Conventional-commit type prefix (`feat`, `fix`,
  `docs`, `test`, `refactor`, `chore`, `build`, `ci`, `perf`, `revert`,
  `rules`). No co-author or "generated by" trailers. Use **Bash heredocs** for
  multi-line commit messages, never PowerShell here-strings.
- **`just ci` must pass**, and `just bindings` must leave no diff.
- **CI never downloads a model.** Every test uses the local fixture server or
  small temporary files.
- **Only pinned files are downloadable.** No search, no pasted URLs, no HF
  token, no concurrent downloads. Out of scope; do not add them.
- **Never delete a source file before its destination verifies.**

## Task 1: Pin the models

### Curating the pins

Hashes cannot be invented. Fetch each from the Hugging Face API, which exposes
Git-LFS object IDs — **the LFS oid is the file's SHA256** — without downloading:

```bash
curl -s "https://huggingface.co/api/models/<repo>/tree/main" \
  | python -c "
import json,sys
for f in json.load(sys.stdin):
    n = f.get('path','')
    if n.endswith('.gguf'):
        print(n, f.get('size'), (f.get('lfs') or {}).get('oid'))
"
```

Verified working against `bartowski/Qwen2.5-7B-Instruct-GGUF`, which returns
`Qwen2.5-7B-Instruct-Q4_K_M.gguf 4683074240 65b8fcd9…1423`.

**Pin only `Q4_K_M` in this task, and only these models.** They are the ones
most likely to be wanted and small enough to be plausible downloads:

| Registry id       | Suggested repo (verify it exists and is ungated) |
| ----------------- | ------------------------------------------------ |
| `qwen2.5-0.5b`    | `bartowski/Qwen2.5-0.5B-Instruct-GGUF`           |
| `qwen2.5-7b`      | `bartowski/Qwen2.5-7B-Instruct-GGUF`             |
| `llama-3.2-1b`    | `bartowski/Llama-3.2-1B-Instruct-GGUF`           |
| `llama-3.2-3b`    | `bartowski/Llama-3.2-3B-Instruct-GGUF`           |
| `llama-3.1-8b`    | `bartowski/Meta-Llama-3.1-8B-Instruct-GGUF`      |

model unpinned and say so in your report. An unpinned model is a cell with no
button; a wrong pin is a download that fails confusingly.

```rust

    fn a_recorded_model_is_found_again() { /* record then path_of */ }

    #[test]
    fn a_record_whose_file_vanished_is_reported_missing_not_present() {
        // Files live wherever the user chose, including a removable drive.
        // Listing a model as ready when its bytes are gone produces a failure
        // at load time, further from the cause and with a worse message.
        let root = tempfile::tempdir().unwrap();
        let store = ModelStore::new(root.path().join("models.json"));
        let gone = root.path().join("absent.gguf");
        store.record(ModelRecord { path: gone, ..sample() }).unwrap();

        assert!(store.present().is_empty());
        assert_eq!(store.records().len(), 1, "the record itself must survive");
    }

    #[test]
    fn the_url_is_derived_and_cannot_vary_by_host() {
        // Storing a full URL per entry would let the host differ per model --
        // a wider trust surface, widened somewhere nobody would look.
        assert_eq!(
            download_url("bartowski/Qwen2.5-7B-Instruct-GGUF", "a.gguf"),
            "https://huggingface.co/bartowski/Qwen2.5-7B-Instruct-GGUF/resolve/main/a.gguf"
        );
    }

    #[test]
    fn an_index_that_will_not_parse_is_an_empty_library_not_a_crash() {

        // power cut mid-write.

        assert!(ModelStore::new(root.path().join("models.json")).records().is_empty());
    }

    #[test]
    fn forgetting_a_model_removes_only_that_record() { /* two records, forget one */ }
```

## Task 3: Resumable verified download

**Files:** Modify `crates/osstat-inference/src/download.rs`.

**Produces:** `pub async fn download_resumable(url: &str, part: &Path,
destination: &Path, expected_sha256: &str, expected_size: u64, on_progress: impl
FnMut(Progress)) -> Result<(), AcquireError>`

Leave `download_verified` untouched — the runtime path still uses it, and its
stream-hashing is correct for a non-resumable 34 MB file.

- [ ] **Step 1: Write the failing tests**

Extend the existing `serve_once`-style fixture. Required cases:

```rust
    #[test]
    fn an_interrupted_download_resumes_from_where_it_stopped() {
        // The case the whole function exists for. The fixture serves the first
        // half, drops the connection, and asserts the retry carries
        // `Range: bytes=<half>-` and that the reassembled file hashes correctly.
    }

    #[test]
    fn a_server_ignoring_range_restarts_rather_than_corrupting() {
        // A 200 with the whole body answering a ranged request must truncate
        // the .part and start over. Appending would produce a file that is
        // simply wrong, failing its hash for a reason nobody could diagnose.
    }

    #[test]
    fn a_hash_mismatch_leaves_nothing_usable() {
        // Neither the .part nor the destination may survive: a leftover .part
        // would be resumed next time and fail identically, forever.
    }

    #[test]
    fn the_destination_appears_only_after_the_hash_matches() {
        // Nothing partial may ever be mistaken for a usable model.
    }

    #[test]
    fn a_size_that_disagrees_with_the_pin_is_refused_before_hashing() {
        // Cheap early rejection: a wrong size means the upload changed, and
        // saying so beats a hash mismatch the user will read as corruption.
    }
```

- [ ] **Step 2: Run and confirm they fail.**

- [ ] **Step 3: Implement**

Sequence: check `part` length → if non-zero send `Range: bytes=N-` → if the
response is `206`, append; if `200`, truncate and write from zero → on
completion compare length to `expected_size`, then hash the whole file in one
pass → compare to `expected_sha256` → `fs::rename` into `destination` → on any
mismatch remove both `part` and `destination`.

Report progress as bytes-so-far against `expected_size`, including the bytes
already present when resuming, or a resumed download appears to restart.

- [ ] **Step 4: Run the tests and the gate.**

- [ ] **Step 5: Prove the resume test is load-bearing**

Break it: ignore the existing `.part` length and always request from zero while
still appending. Confirm
`an_interrupted_download_resumes_from_where_it_stopped` fails, paste the output,
restore, confirm green. Record both outcomes.

**Files:** Create `src-tauri/src/models.rs`; modify `src-tauri/src/lib.rs`,
`src-tauri/Cargo.toml` if needed.

**Read `src-tauri/src/runtime.rs` first and match it exactly** — event
constants, spawned tasks, error payloads, command registration. There is one
convention in this codebase; do not add a second.

Commands: `models_catalogue` (registry cells joined with what is downloaded),
`models_download(model_id, quant_id)`, `models_cancel`, `models_delete`,
`models_folder`, `models_set_folder(path)`, `models_plan_move(path)`,
`models_move(path)`.

Events: `model:progress`, `model:done`, `model:failed`.

Requirements:

- **Free space is checked before any request**, using `fs4` as
  `acquire.rs` already does, and refused with the shortfall named.
- **One download at a time.** A second request is refused naming the file in
  progress.
- **The folder setting** lives with the other Tauri-side settings; unset means
  `<app-data>/models`. Create it on first use.
- `models_delete` removes the file _and_ forgets the record.
